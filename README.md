# Ilham Wara — Portfolio

Personal portfolio for Ilham Wara Nugroho, a senior full stack engineer
building government and enterprise systems.

Built with React 19, TypeScript, Vite 8, TanStack Router, and Tailwind CSS 4.
No backend or database — the site is fully static and deploys as a single-page
app.

## Requirements

- Node.js **22.12+** (Vite 8 and ESLint 10 do not run on older Node releases)
- npm

## Commands

```bash
npm install
npm run dev       # local dev server
npm run build     # type-check + production build
npm run preview   # preview the production build
npm run lint      # ESLint
npm run covers    # regenerate project cover SVGs
```


## Editing content

All project content lives in `src/data/projects.ts`. Each entry is a single
application with its own slug, client, category, summary, tech stack, features,
and responsibilities. Add a new entry to `projects` and it automatically appears
on the project index and gets a detail page at `/projects/<slug>`.

Set `featured: true` to show it on the home page. `latest: true` adds the
"Latest" badge.

`src/data/profile.ts` holds the bio, skills, achievements, and experience
timeline used by the About and Experience pages.

## Project covers

Covers are a mix of **real screenshots** and **illustrative mockups**, and the
site labels each one:

- `public/projects/*-live.jpg` — screenshots of live apps/demo deployments, the
  local Echowheel build, or official app-store listings. See
  [`public/projects/SOURCES.md`](public/projects/SOURCES.md) for URLs and capture
  dates. These are not generated and must be re-captured manually when an app
  changes.
- `public/projects/*.svg` — illustrative mockups generated by
  `scripts/generate-project-covers.mjs`, used for SIGD (public deploy was not
  reachable) and as the EWAS architecture diagram.

`src/data/projects.ts` controls the label through the `preview` field:
`live`, `local`, `store`, `diagram`, or `mockup`.

Regenerate the mockup SVGs after changing the generator:

```bash
npm run covers
```

The generator does **not** overwrite the `*-live.jpg` screenshots. To rasterise
mockup SVGs for social previews, use headless Chrome and ImageMagick:

```bash
for f in public/projects/*.svg; do
  slug=$(basename "$f" .svg)
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless=new --disable-gpu --hide-scrollbars \
    --force-device-scale-factor=1 --window-size=1200,760 \
    --screenshot="/tmp/$slug.png" "file://$PWD/$f"
  magick "/tmp/$slug.png" -strip -quality 86 "public/projects/$slug.jpg"
  rm "/tmp/$slug.png"
done
```

Keep the SVG for on-page rendering (crisp at any size) and the JPG for
`og:image`/social previews.

## Notes

- Every route sets its own title, description, canonical URL, and Open Graph
  metadata through TanStack Router's `head` API. `<HeadContent />` is rendered
  in the root layout; without it route metadata is not applied.
- Project filter controls are buttons rather than `<select>` elements, so no
  custom select library is required.
- The site uses `prefers-reduced-motion` to disable the marquee and reveal
  animations.
